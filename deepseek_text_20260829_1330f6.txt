ЗАДАНИЕ: РАЗРАБОТАТЬ СИСТЕМУ АНАЛИЗА ЧАТОВ С ДОЛГОВРЕМЕННОЙ ПАМЯТЬЮ

================================================================================
1. ОПИСАНИЕ ПРОБЛЕМЫ
================================================================================

У меня есть несколько чатов (групп) с перепиской. Я хочу анализировать их с 
помощью ИИ, отправляя запросы по API и получая структурированный ответ 
(список задач, статусы, что в работе, что завершено).

ПРОБЛЕМА №1: Как обновлять анализ, когда появляются новые сообщения?
- Нельзя каждый раз отправлять ВСЮ историю переписки (она растёт, дорого, 
  долго, ИИ путается).
- Нужно отправлять только НОВЫЕ сообщения + краткую выжимку (суммаризацию) 
  того, что было раньше.

ПРОБЛЕМА №2: Что делать со старым анализом?
- Старый анализ содержит задачи, которые уже решились (например, "покрасить 
  забор" — забор уже покрашен, но в старом анализе он всё ещё висит).
- Если я просто склею старый анализ + новые сообщения, ИИ не поймёт, что 
  "покраска забора" уже не актуальна, и будет тащить её в новый отчёт.

ПРОБЛЕМА №3: Что делать с историей?
- Удалять старые анализы нельзя (они нужны для понимания хода работы).
- Но засорять ими ИИ тоже нельзя.

================================================================================
2. РЕШЕНИЕ (АРХИТЕКТУРА)
================================================================================

Нужно внедрить систему, которая работает по принципу "Скользящее окно с 
суммаризацией" (Sliding Window with Summarization).

ЭТАП 1: Структура хранения данных для каждого чата

Для каждого чата в базе данных (или в JSON-файле) должны храниться два поля:

1. "Актуальное резюме" (current_summary)
   - Это краткий, сжатый анализ последнего состояния чата.
   - Содержит только ТЕКУЩИЕ задачи (без завершённых).
   - Это единственное, что мы будем отправлять ИИ вместе с новыми сообщениями.

2. "История резюме" (history_summaries)
   - Это список всех предыдущих версий резюме.
   - Хранится только для отчётов и аудита.
   - В запросы к ИИ НЕ отправляется!

ЭТАП 2: Процесс обновления (когда приходят новые сообщения)

ШАГ 1: Берём последнее "Актуальное резюме" (допустим, в нём задачи: А, Б, В).
ШАГ 2: Берём НОВЫЕ сообщения, которые пришли после создания этого резюме.
ШАГ 3: Отправляем ИИ запрос со следующей структурой:

------------------------------------------------------------
"Вот текущее состояние чата (анализ на дату Х):
[СЮДА ВСТАВЛЯЕМ current_summary]

Теперь новые сообщения за период Y:
[СЮДА ВСТАВЛЯЕМ НОВЫЕ СООБЩЕНИЯ]

Обнови анализ, следуя правилам:
1. Если в новых сообщениях есть указание, что задача выполнена (например, 
   "забор покрашен", "готово", "сделали") — УДАЛИ эту задачу из финального 
   списка.
2. Если появились новые задачи — ДОБАВЬ их в список.
3. Если задача уже была, но её статус изменился (например, "в работе" -> 
   "ожидает") — ОБНОВИ статус.
4. Итоговый ответ выдай в виде: 
   "Актуальные задачи: ..." и "Что завершено за период: ..."
5. НЕ включай в актуальный список завершённые задачи.
------------------------------------------------------------

ШАГ 4: Получаем от ИИ новый обновлённый анализ (new_summary).
ШАГ 5: В базе данных ДЕЛАЕМ ДВА ДЕЙСТВИЯ:
   - Старую версию current_summary переносим в history_summaries (сохраняем 
     с датой).
   - Заменяем current_summary на new_summary (это теперь актуальное состояние).
ШАГ 6: В следующий раз при обновлении берём уже ЭТОТ новый current_summary.

ЭТАП 3: Что происходит со старыми завершёнными задачами

- Когда забор покрашен, ИИ на основе новых сообщений понимает, что задача 
  выполнена, и НЕ включает её в new_summary.
- Таким образом, в current_summary задача "покрасить забор" исчезает навсегда 
  (для рабочих запросов).
- Но если вам нужно посмотреть историю (что делали месяц назад), вы открываете 
  history_summaries и видите там старую версию с этой задачей.

================================================================================
3. КЛЮЧЕВЫЕ ПРИНЦИПЫ (ЧТО ДЕЛАТЬ И ЧТО НЕ ДЕЛАТЬ)
================================================================================

ПРАВИЛЬНО:
✅ Хранить только ОДНО актуальное резюме на чат.
✅ При обновлении заменять его новым (а не дополнять старый).
✅ Отправлять ИИ только ОДНО резюме + НОВЫЕ сообщения.
✅ Старые резюме складывать в историю (не удалять).
✅ В промпте чётко указывать ИИ удалять выполненные задачи.

НЕПРАВИЛЬНО:
❌ Не копить все старые анализы и не отправлять их ИИ (это перегружает и 
   путает ИИ).
❌ Не просто добавлять новые задачи к старым (так забор никогда не исчезнет).
❌ Не удалять старые анализы безвозвратно (потеряете историю).

================================================================================
4. ЧТО НУЖНО РЕАЛИЗОВАТЬ (СПИСОК ТРЕБОВАНИЙ)
================================================================================

1. Создать систему хранения для каждого чата, где есть:
   - current_summary (строка, актуальный анализ)
   - history_summaries (список словарей вида {дата: "текст"})
   - last_updated (дата последнего обновления)

2. Написать функцию обновления, которая:
   - Принимает chat_id и список новых сообщений.
   - Формирует промпт для ИИ (старое резюме + новые сообщения).
   - Отправляет запрос к ИИ.
   - Получает ответ.
   - Сохраняет старую версию в историю.
   - Перезаписывает current_summary новым ответом.

3. Настроить ИИ (через системный промпт) на строгое выполнение правил:
   - Удалять выполненные задачи из итогового списка.
   - Обновлять статусы существующих задач.
   - Добавлять только действительно новые задачи.

4. Предусмотреть возможность просмотра истории изменений (для отчётов).

================================================================================
5. ПРИМЕР РАБОТЫ СИСТЕМЫ (ДЛЯ НАГЛЯДНОСТИ)
================================================================================

ДЕНЬ 1 (первый анализ):
- Отправляем ИИ все старые сообщения.
- Получаем current_summary = "Задачи: А, Б, В. В работе: А."

ДЕНЬ 2 (пришли новые сообщения):
- Берём current_summary ("Задачи: А, Б, В").
- Берём новые сообщения: "Задача В выполнена. Появилась задача Г."
- Отправляем это ИИ.
- Получаем new_summary = "Задачи: А, Б, Г. В - завершена."
- Сохраняем старый current_summary в history.
- Перезаписываем current_summary на new_summary.

ДЕНЬ 3 (пришли новые сообщения):
- Берём current_summary ("Задачи: А, Б, Г").
- Берём новые сообщения: "Задача А закрыта. Появилась задача Д."
- Отправляем это ИИ.
- Получаем new_summary = "Задачи: Б, Г, Д. А - завершена."
- Снова сохраняем старый current_summary в history.
- Перезаписываем current_summary на new_summary.

ИТОГ:
- В любой момент в current_summary лежат ТОЛЬКО актуальные задачи.
- В history лежат все старые версии (видно эволюцию).
- ИИ не перегружен, ответы быстрые и точные.

================================================================================
6. ДОПОЛНИТЕЛЬНЫЕ РЕКОМЕНДАЦИИ
================================================================================

- Используйте системный промпт для ИИ, где жёстко пропишите правила 
  обновления (чтобы не забывать удалять выполненные задачи).
- Если в чате очень много новых сообщений, разбивайте их на порции 
  (например, обновляйте анализ каждые 10-15 сообщений).
- Храните current_summary в сжатом виде (не больше 1-2 абзацев), чтобы 
  экономить токены.
- В истории можно хранить не все версии, а только самые важные (раз в день).

================================================================================
ИТОГОВАЯ ЦЕЛЬ: Система, которая автоматически обновляет аналитику по чатам, 
убирает закрытые задачи, добавляет новые и никогда не перегружает ИИ лишней 
информацией. Всё, что вам нужно — это current_summary + новые сообщения.
